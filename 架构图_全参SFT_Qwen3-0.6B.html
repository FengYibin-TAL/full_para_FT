Qwen3-0.6B 全参 SFT 系统架构

本架构图对应 `sft-helloworld-train.ipynb` 与 `sft-helloworld-inference.ipynb`。 整体逻辑遵循“环境准备 → 基座模型加载 → 数据集映射 → SFT 训练 → 最优模型保存 → 推理验证”的闭环流程。 全参训练的关键特征是：基座模型全部参与反向传播，训练逻辑简单直接，但参数更新范围最大。

1训练主流程
环境与依赖层
Notebook 启动后首先建立运行环境
  • 设置 `HF_ENDPOINT` 与 `HF_HOME`
  • 安装 `trl`、`datasets`
  • 准备 Hugging Face 缓存目录
模型与Tokenizer层
构造训练的基础语义表示能力
  • 加载 `AutoModelForCausalLM`
  • 加载 `AutoTokenizer`
  • 基座为 `Qwen3-0.6B`
数据处理层
将业务 JSONL 转为 TRL 可消费格式
  • 读取 `train/test` JSONL
  • `conversation` 映射为 `messages`
  • 移除冗余字段，保留训练核心列
SFT 训练层
训练器统一调度训练、评估与保存
  • `SFTConfig` 定义超参数
  • `SFTTrainer` 组织数据与损失计算
  • 全量参数参与更新

2训练控制与输出链路
训练控制策略
由 `SFTConfig` 统一定义
  • `max_steps` 控制训练长度
  • `logging_steps` 决定日志频率
  • `eval_steps` / `save_steps` 驱动评估与保存
模型产物输出
训练完成后进入持久化阶段
  • checkpoint 写入 `output_dir`
  • `load_best_model_at_end=True` 载入最优权重
  • 最终导出 `.../sft-full/best`
可观测性
训练过程日志可视化
  • `report_to="tensorboard"`
  • `TENSORBOARD_LOGGING_DIR=/root/tf-logs`
  • 事件文件供 TensorBoard 读取
3推理验证流程
推理加载层
直接加载训练后的最佳目录
  • `model_name = .../sft-full/best`
  • 加载 tokenizer 与微调后模型
  • 推理端与训练端模板保持一致
生成与结果解析层
把业务输入转为模型输出
  • `apply_chat_template` 组织提示词
  • `generate()` 生成关键词结果
  • 分离 thinking / content，提取最终答案
核心逻辑结论：全参 SFT 的系统结构相对直接，训练链路重点在于 “基座模型完整更新 + 标准 SFTTrainer 调度 + 最优模型导出”。 它的优势是流程清晰、实现门槛低；代价是参数更新范围最大，随着模型规模提升，训练成本也会同步增加。
