Qwen3-8B LoRA SFT 系统架构

本架构图对应 `sft-LoRA-train.ipynb` 与 `sft-LoRA-inference.ipynb`。 核心目标是把“8B 基座模型 + 对话式关键词抽取数据 + PEFT LoRA 注入 + SFTTrainer 训练 + adapter 保存 + merge 推理导出”组织成一条清晰且闭环的工程链路。相比全参版本，此架构的关键差异在于： 训练阶段只更新 LoRA 适配器参数，推理阶段可选择“基座+adapter”或“merge 后单模型”两种部署形态。

基座模型
Qwen/Qwen3-8B
训练范式
PEFT LoRA + TRL SFTTrainer
关键输出
adapter 目录 `best` + 可选 merged 模型
1训练准备与依赖约束
环境初始化
先定义下载与缓存环境，再安装依赖
  • 设置 `HF_ENDPOINT`
  • 设置 `HF_HOME`
  • 确保模型缓存落在数据盘
依赖安装
LoRA 训练链条必须具备完整 PEFT 生态
  • 安装 `peft`
  • 安装 `trl`、`datasets`
  • 后续由 `SFTTrainer` 统一调用
内核重启约束
LoRA Notebook 的工程关键约束
  • pip 后必须 `Restart Kernel`
  • 避免 `peft` 未装时已导入 `trl`
  • 避免 reload 导致 `PicklingError`
TRL 导入点
在干净内核里再导入训练器
  • `from trl import SFTConfig, SFTTrainer`
  • 此时 `get_peft_model` 可正常解析
  • 训练器状态保持一致
2训练核心链路
基座模型层
8B 模型提供基础语言理解与生成能力
  • 加载 `Qwen3-8B`
  • 加载 `AutoTokenizer`
  • 训练侧使用 `bfloat16`
数据映射层
业务样本转换为 chat training 格式
  • 读取 `train/test` JSONL
  • `conversation` 转 `messages`
  • 清理无关字段
LoRA 注入层
通过 PEFT 把低秩适配器挂到线性层
  • `r=4`、`lora_alpha=8`
  • `lora_dropout=0.05`
  • `target_modules="all-linear"`
SFT 调度层
控制训练、评估、保存与日志
  • `max_steps=1000`
  • `save/eval/logging` 按 step 调度
  • `report_to="tensorboard"`
adapter 输出层
训练结果先以 LoRA adapter 形态保存
  • checkpoint 保存到 `output_dir`
  • 最终导出 `.../sft-LoRA/best`
  • 供 `PeftModel.from_pretrained` 使用

逻辑重点：LoRA 架构并不是替换基座模型，而是“在基座之上附加 adapter 训练层”。 因此训练输出首先是 adapter，而不是直接得到一个完整的新基座目录。
3推理与部署链路
推理环境层
推理侧同样需要 `peft`
  • 设置 `HF_ENDPOINT` / `HF_HOME`
  • 确保可加载原始基座
  • 安装 `peft` 供 adapter 挂载
基座 + adapter 复原层
恢复训练后的完整语义能力
  • 先加载 `Qwen3-8B` 基座
  • 再 `PeftModel.from_pretrained(.../best)`
  • 推理侧当前使用 `float16`
Merge 层
把 adapter 合并回基座，便于单目录部署
  • `merge_and_unload()`
  • 得到 `merged_model`
  • 后续 `generate()` 直接基于合并模型
结果与导出层
完成业务输出与可选部署产物保存
  • `apply_chat_template` + `generate`
  • 切分 thinking / content
  • 可 `save_pretrained(.../merged)`

4系统闭环与资源约束
资源敏感点
LoRA 并不等于完全省显存
  • 8B 前向仍占大量激活与 logits 显存
  • `per_device_train_batch_size` 是首要调节点
  • 必要时需加 `max_length`、`gradient_checkpointing`、梯度累积
系统闭环结果
训练、验证、推理、导出构成完整工程链
  • 训练侧产出 adapter 与日志
  • 推理侧支持即时挂载或合并部署
  • 文档、README、Notebook 三者保持一致

关键路径

`.../sft-LoRA/best`

TensorBoard

核心区别

与全参版本相比
训练时不直接更新全部基座权重，而是通过 `LoraConfig` 注入 adapter 进行参数高效微调。
部署形态
可保留“基座 + adapter”组合，也可 merge 为单模型目录，适应不同部署策略。
